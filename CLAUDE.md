# CLAUDE.md

## What This Is

`@upland/shared` — shared modules for the Upland Exhibits app suite. One repo,
ONE package with subpath modules (`@upland/shared/timing`, …), consumed by the
apps as a tag-pinned git dependency:

```json
"@upland/shared": "github:flinthillsdesign/upland-shared#v0.1.0"
```

Single package (not a workspaces monorepo) on purpose: npm can install a whole
git repo by tag but not a subdirectory of one, and we don't publish to a
registry. Apps update deliberately by bumping their pin — never automatically.

## The release ritual

These travel together in ONE commit, always:

1. The change (e.g. edit `TIMING_PROJECTS` in `src/timing.ts`)
2. The pinned-value tests in `test/` (they intentionally fail on data edits —
   update the expected values as part of a deliberate change)
3. The module's version marker (e.g. `TIMING_VERSION`) and `package.json` version
4. Then: `git tag v<version> && git push origin main v<version>`

Roll out by bumping the pin in each consumer
(`npm install github:flinthillsdesign/upland-shared#v<version>`) when that app
is ready. After a timing recalibration, regenerate ODIN's stored retros so
their charts match the new curves (each retro stamps
`confidence.timing_version`).

## Consumers (keep this list current)

| App | Server | Frontend |
|---|---|---|
| upland-scheduler | `lib/coaching.ts` require | `public/js/timing.js` GENERATED by build.js (globals; declarations in `public/js/globals.d.ts`) |
| upland-odin | `lib/retro.ts` require | `public/js/timing.ts` re-export, built with `bundle:true` |

`dates`, `mail` and `db` (v0.4.0) are plain server modules — import the
subpath. `dates` is also safe to bundle into a browser file. Import subpaths,
never the package root, from browser code: the root pulls in `mail`, which
reads `process.env`.

**What belongs here:** code that must behave the same in every app — a rule
about days, how mail leaves, how a dropped connection is retried. Not an app's
words, layout or data. If two apps have their own copy of something and a fix
to one would have to be made in the other, it belongs here.

Frontends can't import node_modules at runtime (both apps serve unbundled
files), so each app's build bakes this package into its browser timing file.
The `prepare` script (tsc → dist/) runs automatically on git installs,
including Netlify's.

## Conventions

- TypeScript, CommonJS output via tsc, `dist/` gitignored, `prepare` builds.
- `npm test` = typecheck + node:test. `npm run lint` = oxlint. CI runs both.
- New shared module = new file in `src/`, an export line in `src/index.ts`, a
  subpath entry in package.json `exports`, tests, and a row in the README.
  Planned next: `contracts` (cross-app API shapes), `voice` (Upland style
  guide + prompt fragments).
